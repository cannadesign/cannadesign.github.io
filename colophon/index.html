Built for people, and for the AI that reads on their behalf.

Recruiters increasingly ask an AI assistant about a candidate before they open a portfolio. This site is designed so that answer is accurate, specific and points back here. It is the same principle as the work: decide what the reader needs, then make it impossible to miss.

  1. One entity, everywhere

    Guilherme Cannalonga, Senior Product Designer, Greater Boston: the same name, title and location on this site, the résumé and LinkedIn, tied together with schema.org sameAs so a model doesn’t merge me with someone else.

  2. Structured data on every page

    A JSON-LD graph: a Person with occupation, location, skills and education; a ProfilePage and WebSite on the home page; an Article with author, subject and outcome on each case study, plus breadcrumbs.

  3. Answers in the first lines

    Every case opens with a short version (problem, what I did, outcome) and states its numbers in plain sentences, so a model can quote them without reconstructing context.

  4. Readable without JavaScript

    The full English text is in the HTML itself; the language toggle only swaps it. Crawlers that don’t run scripts read the same page you do.

  5. An llms.txt

    /llms.txt is a plain-text summary written for language models, and /llms-full.txt carries the full text of every case study.

  6. AI crawlers welcome

    robots.txt explicitly allows search and assistant crawlers (OpenAI, Anthropic, Perplexity, Google, Apple, Microsoft), and a sitemap lists every page with its last update.

  7. Claims a model can repeat safely

    Every number says how it was measured and what it leaves out, and anything I couldn’t verify is not on the site. An answer engine repeats what it finds, so the page has to be right first.
